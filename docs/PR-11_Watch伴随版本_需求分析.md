# PR-11 Apple Watch 伴随版本需求分析

| 版本 | 日期 | 依赖 |
|---|---|---|
| v1.0 | 2026-05-29 | PR-01~PR-10（Core MVP + 模板与动作库 CRUD + 训练日历安排 + 首页重设计完成） |

---

## 1. 目标

### 1.1 解决的问题

力量训练中有三个高频的「手机交互障碍」场景：

1. **组间休息**：组间低头解锁手机查看倒计时，打断注意力；休息计时的通知出现在屏幕顶部，转瞬即逝，错过后需要重新操作
2. **记录一组**：卧推、深蹲等大重量动作完成后，手机往往在离身处（旁边的凳子、腰包）；站起来找手机、解锁、定位到当前动作，这段操作流程打断了训练节奏
3. **手机不在身边**：部分用户将手机锁入储物柜，整个训练过程中与手机物理隔离

Apple Watch 贴在手腕上，与手机的互补关系正好覆盖以上三个场景。

### 1.2 目标场景

- 训练中，用户不拿起手机，在手腕上完成「记录这一组」的操作（重量、次数、RPE、左/右侧）
- 组间休息时，Watch 显示倒计时，到时震动提醒，用户一眼确认该继续了
- 手机放在包里或旁边未激活状态时，Watch 上的计时和记录操作不受影响

### 1.3 核心价值

**训练中手不离铁，Watch 在腕，数据不漏。**

## 2. 设计原则

1. **Watch 是伴随设备，不是独立 App**：iPhone 是训练数据的唯一权威来源，第一版 Watch 不承担完整训练管理职责；Watch 的价值在健身房环境下的交互便利，而非功能完整性
2. **每一步操作控制在 5 秒以内**：Watch 屏幕小、出汗影响触摸精度；与其追求全功能覆盖，不如把核心流程做到极致流畅
3. **通信中断不能丢失已完成的动作**：iPhone 和 Watch 之间的连接随时可能短暂断开；凡是用户在 Watch 上已确认的记录，不能因通信抖动而丢失
4. **Watch UI 独立重新设计，不搬运 iPhone 界面**：iPhone 和 Watch 的交互方式根本不同，Watch 界面不是 iPhone 页面的等比缩小

## 3. 范围

### 3.1 本次做

| 功能 | 说明 |
|---|---|
| 当前训练状态展示 | 显示进行中的训练名称、动作列表、每个动作已完成组数 |
| 快速记录一组 | 在 Watch 上输入重量、次数、可选 RPE 和左/右侧；数据传回 iPhone 落库 |
| 参考上组数据 | 进入动作时，展示该动作上一组的重量和次数，供用户参考 |
| 休息计时器 | 完成一组后自动启动倒计时；支持跳过、延长 30 秒；到时震动提醒 |

### 3.2 本次不做

| 项 | 说明 |
|---|---|
| Watch 独立开始/结束训练 | 第一版由 iPhone 发起训练，Watch 加入已有 session |
| 模板与动作库管理 | 不在 Watch 上做配置类操作 |
| 训练历史浏览 | 不在 Watch 上查看历史记录或统计 |
| CSV 导出 | 不适合 Watch 场景 |
| HealthKit Workout 集成 | 有价值，涉及额外权限和 Workout session 生命周期，留给后续版本 |
| 表盘 Complication / Smart Stack | 可作为后续增强；不作为第一版核心功能 |
| Watch 离线独立训练 | 手机完全不在范围内时独立完成完整训练，复杂度高，留给后续版本 |
| 在 Watch 上修改或删除已记录的组 | 第一版只支持新增，修正操作在 iPhone 上完成 |

## 4. 设备角色与数据流

**iPhone**：训练数据的唯一权威来源。负责存储所有训练记录，是 Watch 所需训练信息的来源，也是 Watch 发出的记录事件的最终落库方。

**Watch**：训练中的交互遥控器。只在训练进行中提供价值，不持久存储完整业务数据；但可为已确认记录保留待同步事件队列，直到 iPhone 明确确认落库。Watch 需要能在 iPhone 临时不可达时（用户离手机几步远、手机锁屏后短暂延迟）继续独立运行休息计时器。

**数据流向（需求层面描述，不锁定通信方案）**：

| 方向 | 内容 |
|---|---|
| iPhone → Watch | 当前训练快照：训练名称、动作列表、各动作已完成组数、上组数据 |
| Watch → iPhone | 用户完成一组的记录事件：重量、次数、RPE、左/右侧、完成时间 |

## 5. 功能需求

### 5.1 当前训练状态展示

| 状态 | Watch 展示 |
|---|---|
| 无进行中的训练 | 显示等待状态，提示在 iPhone 上开始训练后才可使用 |
| 有进行中的训练 | 显示训练模板名称 + 动作列表（每个动作标注已完成组数） |
| 训练结束 | Watch 退出训练中状态，返回等待页 |

iPhone 端训练状态发生变化（开始/结束）后，Watch 应在合理延迟内更新。

### 5.2 快速记录一组

用户在 Watch 上完成单次记录的交互流程：

1. 从动作列表选择当前动作
2. 输入重量（数字；单位跟随 iPhone 的 kg/lb 设置）
3. 输入次数（正整数）
4. 可选：输入 RPE（6 / 7 / 8 / 9 / 10）
5. 若为单侧动作：选择左侧或右侧（双侧动作此步骤跳过）
6. 确认提交

记录确认后：
- Watch 给出视觉或触觉反馈，告知记录已发送
- 自动进入休息计时器
- 当前动作的已完成组数更新

**单侧动作的侧别推断**：若该动作在当前 session 内左/右侧组数不平衡，Watch 应推断并预选组数较少的一侧，用户可覆盖。

**重量和次数的输入方式**：应采用选择器或拨盘风格的控件（而非文字键盘），以适应出汗、单手操作、手套等健身房实际环境。

### 5.3 休息计时器

| 行为 | 说明 |
|---|---|
| 自动启动 | 完成一组记录后，以该动作的默认休息时间启动倒计时 |
| 倒计时显示 | 突出显示剩余时间（秒数） |
| 震动提醒 | 倒计时归零时 Watch 震动，提醒用户可以开始下一组 |
| 跳过 | 用户可提前结束计时，返回动作列表或记录界面 |
| 延长 30 秒 | 计时中或归零后可追加 30 秒 |
| 手机不可达时 | 休息计时器在 Watch 本地独立运行，不依赖与 iPhone 的实时连接 |
| Watch 腕向下后恢复 | 重新抬腕时，剩余时间应基于实际流逝时间正确显示，不出现「时间冻结」 |

> **注**：watchOS 不保证后台计时器进程在腕向下期间持续运行。计时逻辑应以「目标结束时刻」为锚点，而非依赖持续递减的计数进程。这是 watchOS 平台约束，工程侧需相应设计计时方案。

### 5.4 参考上组数据

进入某个动作的记录界面时，展示该动作最近一组的重量和次数：

- 优先展示当前 session 内该动作的最近一组
- 若当前 session 尚未记录该动作，展示历史任意 session 的最近一组
- 此数据仅供参考展示，不强制预填输入框；用户需主动确认或修改后才能提交

## 6. 体验约束

以下约束来自 Watch 硬件特性和健身房使用环境，工程与设计侧需在此范围内寻找方案：

| 约束 | 来源 | 对设计的影响 |
|---|---|---|
| 单次记录操作完成时间 ≤ 5 秒 | 出汗影响触摸精度；组间注意力有限 | 输入方式必须支持选择器/拨盘，不应依赖软键盘 |
| 腕向下后计时仍需准确 | watchOS 不保证后台计时进程 | 计时逻辑以目标结束时刻为基准 |
| 记录流程步骤数应尽量少 | Watch 屏幕小，多层级导航体验差 | 在功能和流程层级之间做取舍 |
| 单侧动作的侧别选择应支持单手触摸 | 训练时另一只手可能持铁 | 选择控件触摸面积需足够大 |
| 震动提醒需能被手腕感知 | 健身房噪音环境；用户注意力不在手腕 | 使用具有存在感的触觉类型，不使用弱震动 |

## 7. 开放问题

以下问题需要在工程或产品层面进一步决策，本文档不锁定答案：

| 问题 | 背景 |
|---|---|
| 手机锁入储物柜时的数据可靠性 | 用户将手机锁入储物柜后 Watch-iPhone 通信中断；Watch 上已确认的记录必须进入本地待同步队列并在连接恢复后提交到 iPhone。后续需决策队列持久化范围、确认回执、重试退避和重复提交去重策略。 |
| 重量单位的同步方式 | iPhone 支持 kg/lb 切换；Watch 是与 iPhone 单位设置实时联动，还是只在训练快照中带入当前单位？ |
| 记录发送失败时的用户提示策略 | Watch 发出记录事件但 iPhone 未在预期时间内确认时，Watch 应静默重试、显示警告，还是要求用户在 iPhone 上手动确认？ |
| 「上组数据」的历史深度 | 跨 session 的历史数据是否有必要在 Watch 上展示？还是只看当前 session 已足够辅助判断当前组负荷？ |
| Watch 端的错误反馈粒度 | RPE 不合法、动作不存在等校验失败时，Watch 应以何种形式告知用户（考虑 Watch 小屏的展示能力）？ |

## 8. 验收标准

- 当 iPhone 上有进行中的训练时，Watch 应在合理延迟内显示该训练的动作列表及各动作已完成组数
- 当 iPhone 上无进行中的训练时，Watch 应显示等待状态，不展示空训练列表
- 当用户在 Watch 上完成一组记录操作并确认后，该组数据应在 iPhone 的当前训练页正确出现
- 当用户在 Watch 上完成记录后，Watch 侧对应动作的已完成组数显示应随之更新
- 当用户完成一组记录后，休息计时器应自动以该动作的默认休息时间启动倒计时
- 当倒计时归零时，Watch 应震动提醒用户
- 当用户点击「跳过」时，计时器停止，Watch 返回动作列表或记录界面
- 当用户点击「+30 秒」时，剩余时间应增加 30 秒
- 当 Watch 腕向下后重新抬起时，剩余倒计时时间应与实际流逝时间一致，不出现时间冻结
- 当 iPhone 与 Watch 通信短暂中断时，Watch 上正在进行的倒计时不应受影响
- 当动作为单侧动作时，记录流程应出现左/右侧选择步骤；双侧动作不出现此步骤
- 当在当前 session 内已有该动作记录时，进入记录界面应展示该 session 内最近一组的重量和次数
- 当在当前 session 内无该动作记录时，应展示历史最近一组的重量和次数
- 当 iPhone 结束训练后，Watch 侧应退出训练中状态并显示等待页
- 当 Watch 上存在单侧动作且当前 session 左/右侧组数不平衡时，进入记录界面应预选组数较少的一侧
